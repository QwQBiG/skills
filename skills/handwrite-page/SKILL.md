# 把正文写到信纸上

素材和脚本位于本文件所在的 Skill 目录，默认使用[红线信纸模板](assets/paper/red-ruled/template.json)。任务输入与输出保存在用户当前工作目录。每次生成都打开样稿，观察整行的笔迹和间距。

## 准备一页

1. 以本次用户给出的正文为底稿。保留大小写、运算符、括号、代码缩进和指定换行。样稿中的题目、答案和批注只用于观察。只有用户要求补写答案时才拟正文。
2. 打开模板配置及其 `photo`。按 [笔迹参考索引](references/handwriting.md) 选择并查看最相关的原图。一般正文看编号叙述，技术内容加一张缩写或流程图。照片只决定纸面和光影。
3. 在 `output/<本次任务>/` 保存正文并安排物理行。红线底片有 14 条可用实线，另有上下双线与日期栏。正文默认从第一条可用实线起写，段末留白。长文自然分页。代码按原缩进换算成统一的水平距离；太长时先调整页面安排。双层分式或上下标可多留一条空行。

## 生成墨迹

调用 Codex 内置图像生成，传入选好的手稿原图作为视觉参考，开启透明背景。要求在一张横向画布中连续书写本次的几行文字，墨迹为深色，每行之间留出可裁切的空白。提示词包含本批逐行原文、这些行在同一段中的关系、参照图上要观察的位置。指定不画纸、红线、投影或额外说明。保留手写时的宽窄变化与自然字距。

例如处理含箭头的一行时，可以指定“参照流程样稿下半部的箭头长度、字母高度和中英文间隙。用同一支笔逐字书写下面的原文，保留箭头方向与数量”。把生成的透明 PNG 保存到本次任务目录。视觉检查透明区域和逐行内容，发现错漏仅重做相应行组。对代码逐项核对操作符、大小写和标点；无法确认的字符在交付时标明。

## 贴回实拍底片

为同页墨迹建 `page.json`。每项对应一行；同一张多行 PNG 可反复引用，通过 `crop` 指明该行在源图中的矩形。下例中的文件名和裁切坐标需按实际生成结果填写。

```json
{
  "lines": [
    {"row": 1, "file": "ink.png", "crop": [0, 0, 1400, 240]},
    {"row": 2, "file": "ink.png", "crop": [0, 240, 1400, 480], "indent_px": 96}
  ]
}
```

单行 PNG 可省略 `crop`。文件相对于任务 JSON。裁切坐标为左、上、右、下，右和下均不含边界。程序自动去掉行周围的透明留白，按字高等比缩放，沿红线弯曲合成。缩进由 `indent_px` 指定。默认高度适合含普通汉字的一行；纯标点、上标或分式用 `height_px` 指定整行墨迹高度。`baseline` 是落线在墨迹高度中的相对位置，默认 0.92，长下伸笔画可适当调小。

在用户工作目录运行。Python 环境需安装 Pillow。将下面的 Skill 路径换为本文件所在目录，任务名换为实际名称。

```powershell
$skill = (Resolve-Path -LiteralPath ".agents/skills/handwrite-page").Path
python "$skill/scripts/compose.py" "$skill/assets/paper/red-ruled/template.json" "output/demo/page.json" "output/demo/page-01.png"
```

检查退出码，再打开整页与局部核对正文、箭头方向、缩进、行尾和纸张边缘。行过宽时重新安排换行；多页分别使用各页的任务 JSON。成图沿用底片的原始像素与手机光影。目前没有实测纸张毫米尺寸，精确打印时需用户提供纸张宽高。

## 更新素材

- 新纸张在用户工作目录的 `materials/paper/<名称>/` 单独保存照片和同结构的模板。按照片显示方向确定像素坐标，在书写区左右边界和中间若干列测出每条可写实线的 y 值。按新行距设默认墨迹高度，将新模板路径传给脚本。
- 新笔迹整页或整段存入用户工作目录的 `materials/handwriting/`。在该目录记录每张样稿适合的内容和代表性行，后续生成时优先使用用户指定的素材。
